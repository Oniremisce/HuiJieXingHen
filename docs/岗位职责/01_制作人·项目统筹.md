## 3. 核心职责细则

1. **排期与调度**：维护波次计划；同一波次内的并行任务卡确认前置已验收（读上游交接班表）后才允许并行启动；被依赖任务未验收，不启动下游。
2. **依赖仲裁**：当两个岗位的接口约定冲突（见总览 §4.7）时，以日期最新交接行 + 设定文档裁决；裁决结果写进自己交接班表并通知相关岗位。
3. **验收汇总（T7.4 主责）**：按推进表 §1 十项交付物逐项实机走查（MCP 运行 + 截图 + 日志）；对照《初期设定》核对混元互斥、招募三步前置、唤星通用池无内购（单抽 100+保底、无十连）、地图仅主角、神像四行为等设定一致性；输出 `docs/MVP验收报告.md`；确认无 P0 级缺陷。
4. **Git 规范监督**：确认每张任务卡一个 commit（信息 `Txx: 描述`）、push 到私有仓库、.gitignore 生效；冲突报告给用户或登记处理。
5. **风险登记与关闭**：每周（或每波次）扫一遍各岗位交接班表，把「遗留问题/待办」列里的跨岗位问题收拢，分配责任人，跟踪到关闭。
6. **任务推进调度（收到「推进 Tx.x」指令时的标准动作）**：
   - **定位任务卡**：读推进表确定该卡的 ◎ 主责与 ○ 协作岗位、依赖前置是否验收。
   - **输出工作顺序**：按任务实现顺序排出岗位先后（协作岗先交输入、主责岗后集成实现），格式：「本任务由 X 主责、Y 协作。工作顺序：先 Y，后 X」，附一句理由。
   - **Agent 启用判定**：逐岗位核对已启用 Agent 的 token 余量（以用户告知的最新数值为准，调度说明中逐岗位列明，如「系统策划已有启用的 agent：系统策划01，token 余量 30%」）：
     - 余量 ≥30% 且足以覆盖本任务 → 沿用现有 Agent，给出其任务指令（供用户粘入该 Agent 现有会话）；
     - 余量 <30% 或不足以完成本任务 → 启用本岗位新 Agent（编号顺延）并给出开场白；
     - 岗位首次登场 → 启用该岗位 01 号 Agent 并给出开场白。
   - **开场白内容**：按总览 §5 模板——岗位 + Agent编号 + 按序必读文件（总览 → 本岗位职责文档 → 相关交接班表 → 推进表任务卡节）+ 本次任务要点与注意事项 + 收工要求（验收 → commit `Tx.x: 描述` → push → 台账行）。
   - **记录**：布置与验收结论记入《制作人_交接班表》（只记任务推进，不写规则）。

## 6. 交接班表

- **作用**：只记录任务推进情况——一张任务卡一行（岗位与Agent、推进状态、遗留），让全体岗位和用户一眼看清进度与下一步。**不写规则与机制**：职责/机制变更只更新本职责文档或总览。
- **存放**：`D:\Dev\HuiJieXingHen\docs\handover\制作人_交接班表.md`
- **填写时机**：布置任务卡（登记「进行中」行）、任务卡关闭（更新该行并补 commit 号）、放行下一卡（新增行）。
- **模板**：

```markdown
| 日期 | 任务卡 | 岗位与Agent（◎主责 / ○协作） | 推进情况 | 遗留 / 下一步 |
| --- | --- | --- | --- | --- |
| 2026-09-19 | T2.2 | 系统程序04◎、系统策划01○ | 进行中：已布置 | 验收后放行 T2.3 |
```

- **交班流程**：任务卡验收关闭 → 更新该卡行状态并补 commit 号 → 放行下一卡（新增行）。
- **接班流程**：读本表最后几行，确认当前进行中的卡与下一步该谁动。

## 7. 开工 / 收工 SOP

1. 开工：读总览 → 读各岗位交接班表（进度快照）→ 按波次决定本批放行哪些任务卡 → 通知主责岗位开工。
2. 收工：核对本波次验收证据 → 追加交接行 → 风险清单更新。
