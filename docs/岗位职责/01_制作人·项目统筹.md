## 3. 核心职责细则

1. **排期与调度**：维护波次计划；同一波次内的并行任务卡确认前置已验收（读上游交接班表）后才允许并行启动；被依赖任务未验收，不启动下游。
2. **依赖仲裁**：当两个岗位的接口约定冲突（见总览 §4.7）时，以日期最新交接行 + 设定文档裁决；裁决结果写进自己交接班表并通知相关岗位。
3. **验收汇总（T7.4 主责）**：按推进表 §1 六项交付物逐项实机走查（MCP 运行 + 截图 + 日志）；对照《初期设定》核对混元互斥、招募三步前置、唤星通用池无内购、心契同行等设定一致性；输出 `docs/MVP验收报告.md`；确认无 P0 级缺陷。
4. **Git 规范监督**：确认每张任务卡一个 commit（信息 `Txx: 描述`）、push 到私有仓库、.gitignore 生效；冲突报告给用户或登记处理。
5. **风险登记与关闭**：每周（或每波次）扫一遍各岗位交接班表，把「遗留问题/待办」列里的跨岗位问题收拢，分配责任人，跟踪到关闭。

## 4. 与其他岗位的协作接口

- **对全体岗位**：只读他们的交接班表，不直接改他们的文件；需要他们行动时，通过提示/消息明确指出「读我交接班表第 X 行」。
- **对用户**：重大决策（Git 仓库创建、范围变更、验收不通过）必须汇报；验收证据以 MCP 截图/日志为准。
- **对系统程序**：T0.1 中 GitHub 私有仓库首次创建若需人工操作，由你引导用户用 GitHub Desktop 完成一次，之后交给 agent 用 CLI。

## 6. 交接班表

- **作用**：让全体岗位和用户知道当前进度、依赖状态、风险清单，以及下一步该谁动。
- **存放**：`D:\Dev\HuiJieXingHen\docs\handover\制作人_交接班表.md`
- **填写时机**：每个波次结束；每次依赖仲裁/验收汇总后；风险状态变化时。
- **模板**：

```markdown
| 日期 | 任务卡/事件 | Agent编号 | 本次做了什么 | 产出/改动文件 | 关键决策与接口约定 | 验证证据 | 遗留问题/待办 | 需通知的下游岗位 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 2026-09-19 | 波次1 | 制作人01 | 确认 P0 四卡验收，启动波次2 | 无 | 波次2 = P1∥P2 并行 | 各岗位交接表验证列 | T1.6 等待美术布置建议 | 系统程序、战斗程序 |
```

- **交班流程**：波次收尾 → 汇总各岗位交接表 → 追加本岗位交接行 → 通知受影响岗位。
- **接班流程**：开工前读各主责岗位交接班表最后 N 行，确认前置就绪。

## 7. 开工 / 收工 SOP

1. 开工：读总览 → 读各岗位交接班表（进度快照）→ 按波次决定本批放行哪些任务卡 → 通知主责岗位开工。
2. 收工：核对本波次验收证据 → 追加交接行 → 风险清单更新。
