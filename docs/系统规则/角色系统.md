## 1. 系统定位与范围

- 本文件整合**所有入队角色（觉醒者）**的全部设定：基本信息、技能形式、阵营体系、数据契约与新增接口，是角色设定的**唯一口径**。
- **不含**：敌人（enemies.csv + 战斗系统 §9 阵型）、主角异乡人（非觉醒者、不参战，见《初期设定》§二）、战斗机制（战斗系统.md）、队伍三态判定（队伍系统.md §5）。
- 数据落位 CSV（characters.csv / skills.csv），**文档=规则与接口，数值=CSV**；新增角色按 §6 接口执行，业务代码零改动。

## 2. 角色基本信息

| 字段 | 规则 | 落位 |
| --- | --- | --- |
| id | `awakened_<体系>_<两位序号>`（如 awakened_mech_01）；体系段 ∈ mech/arcane/xian | characters.csv id 列 |
| name | 正式名，可含全角间隔号「·」（CSV 无转义冲突）；Dialogic Character display_name 直取此列，勿另立名源 | name 列（剧情文案维护） |
| faction | 阵营：机律联邦 / 秘法评议会 / 太微仙盟 | faction 列 |
| system | 体系：机律 / 秘法 / 玄门（§4） | system 列 |
| 四维 | hp / atk / def / spd（战斗属性初值） | hp/atk/def/spd 列（数值策划维护） |
| background | 一句话背景（§5 人设基线的概括）；详细人设由剧情文案在台词中体现，不入 CSV | background 列（T2.9 新增，缺省空容错） |
| portrait_id / sprite_id | 立绘/精灵资源契约 id，走 ArtProvider（T2.6 命名规范） | portrait_id / sprite_id 列 |

## 3. 角色技能形式

- 每角色 **2 个技能**：**小技能**（每轮可用、无消耗）与**大招**（充能 0~上限解锁，释放后归零；机制细节见《战斗系统》§3）。
- 技能数据（skills.csv）：

| 字段 | 规则 |
| --- | --- |
| id | 角色技能 `skill_<体系>_<s1|ult>`；命名沿用既有约定 |
| name | 技能名（战斗 UI/演出显示） |
| type | `small` / `ult` |
| power | 伤害倍率（float，倍率制） |
| target_scope | 攻击范围：single（单体）/ column（整列，上限 3）/ all（全体，上限 6）；组合范围等扩展由战斗系统目标选取器接口预留（枚举定义见《战斗系统》§3.1；列落位=T3.10，数值策划○） |
| effect | 非伤害效果预留列（**缺省空=纯伤害**；MVP 全部技能为纯伤害；后续角色机制如眩晕/护盾等由此扩展，结构化参数随需求另定，落位=T2.9） |
| cutscene_id | 大招演出 id，约定 `cut_<体系>_ult`（小技能留空）；战斗演出消费（《战斗系统》§7） |

- 技能效果表述基准：MVP 三角色技能均为**纯伤害**（小技能倍率 1.2 / 大招 2.5，平衡微调归数值策划）；「技能机制」= 充能制 + scope + 后续 effect 扩展，战斗侧实现一律引用《战斗系统》。

## 6. 新增角色接口（按此流程零代码添加）

1. **设定**：制作人/剧情文案按 §2/§3 字段清单定稿（id/name/faction/system/背景/技能名与效果设想）。
2. **数据**：数值策划填 CSV——characters.csv 一行（§2 全列）+ skills.csv 两行（小技能+大招，§3 全列）。
3. **校验**：跑角色设计器（§7），PASS 后入库存档。
4. **资源**：美术按 T2.6 规范补占位/正式资源（`assets/portraits/<char_id>_<emotion>.png`、8 向帧条命名见推进表 §5.2）。
5. **生效**：DataManager 自动加载；角色列表/编队/战斗/立绘各系统自动消费，**业务代码零改动**。

约束：角色数量无上限（编队上限 3 归 Party）；name 列含「·」直接写；新体系扩展（如第四体系）需制作人裁定后改本文档与体系枚举，不属于常规新增。

## 7. 角色设计器（tools/character_designer.gd，headless 可跑）

| 功能 | 内容 |
| --- | --- |
| 校验 | characters.csv / skills.csv 全行：列数、枚举（system/type/target_scope）、id 规则（§2/§3）、引用存在（skill_small/skill_ult 在 skills.csv 中存在、cutscene_id 符合约定、portrait/sprite 资源文件存在） |
| 冒烟 | DataManager 加载断言（角色数、指定角色字段回读）+ ArtProvider 取占位资源非空 |
| 报告 | 逐项 PASS/FAIL 明细，FAIL 含文件+行号；EXIT=0/1 |

- 使用时机：每次角色 CSV 变更后（新增/改数值/改技能）；与 tools/smoke_test_data_models.gd 互补（后者断言数据模型结构，本工具断言角色内容合规）。

## 8. 职责边界

- **数值策划**：四维/技能数值/权重，CSV 改动复跑设计器。
- **剧情文案**：name/background 文案、人设与台词一致性（人设基线见 §5）。
- **系统程序**：CharacterData/SkillData 模型、CSVParser 容错（新增列缺省值）、角色设计器工具实现。
- **战斗程序**：技能机制实现消费 power/scope/充能（一律引用《战斗系统》，不重复定义）。
- 设定冲突：《初期设定》世界观为最高裁决；体系与队伍规则冲突以《队伍系统》/《战斗系统》为准。
