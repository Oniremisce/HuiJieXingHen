## 1. 系统定位与范围

- 本文件整合**所有入队角色（觉醒者）**的全部设定：基本信息、技能形式、阵营体系、数据契约与新增接口，是角色设定的**唯一口径**。
- **不含**：敌人（enemies.csv + 战斗系统 §9 阵型）、主角异乡人（非觉醒者、不参战，见《初期设定》§二）、战斗机制（战斗系统.md）、队伍三态判定（队伍系统.md §5）。
- 数据落位 CSV（characters.csv / skills.csv），**文档=规则与接口，数值=CSV**；新增角色按 §6 接口执行，业务代码零改动。

### 2.1 角色面板与喂材料升级

- **角色面板**显示：等级（Lv.xx）、**经验条**（当前 exp/升级所需）、四维属性（升级成长预览可选）。
- **喂材料升级**：面板提供升级材料**喂食入口**——选中材料 → 喂食 → 获得经验 → 经验满自动升级（溢出结转）；材料经验值由道具定义（数值策划维护），材料库存走背包接口（T6.1）。
- 升级经验曲线、升级四维成长值=数值策划定值（战斗内属性生效见《战斗系统》§5.1）。

## 3. 角色技能形式

- 每角色 **2 个技能**：**小技能**（每轮可用、无消耗）与**大招**（充能 0~上限解锁，释放后归零；机制细节见《战斗系统》§3）。
- 技能按**目标阵营**分两类：**敌方技能**（target_side=enemy，攻击敌人）与**友方技能**（target_side=ally，治疗/护盾/增伤队友）；两者同走充能与出手规则，目标选择规则见《战斗系统》§8.2。
- 技能数据（skills.csv）：

| 字段 | 规则 |
| --- | --- |
| id | 角色技能 `skill_<体系>_<两位序号>_<s1|ult>`（如 skill_mech_01_s1）；**序号段须与持有角色 id 的序号段一致**（awakened_mech_01 ↔ skill_mech_01_s1 / skill_mech_01_ult）；一角色 = 2 行专属技能，**不跨角色复用** |
| name | 技能名（战斗 UI/演出显示；占位名由剧情文案复核定稿） |
| type | `small` / `ult` |
| target_side | 目标阵营：`enemy`（缺省）/ `ally` |
| target_scope | 目标范围：`single`（单体）/ `column`（整列，**仅敌方**，上限 3）/ `all`（全体）；ally 侧仅用 single/all（我方单列=全体）。列落位=T2.9 |
| effect | 效果枚举：`damage`（缺省）/ `heal` / `shield` / `amp`（见下表）；列落位=T2.9 |
| power | 数值，**按 effect 语义复用**：damage=伤害倍率（×atk）、heal=治疗系数（×atk）、shield=护盾系数（×atk）、amp=增伤百分点（30 即 +30%） |
| cutscene_id | 大招演出 id，约定 `cut_<体系>_ult`（小技能留空）；战斗演出消费（《战斗系统》§7） |

- **效果结算规则**（实现=T3.11，机制细则见《战斗系统》§3.1）：

| effect | 效果 | 结算 |
| --- | --- | --- |
| damage | 伤害（缺省） | 走常规伤害管线（《战斗系统》§4 乘区） |
| heal | 治疗 | 目标恢复 HP = 施法者 atk × power，**上限不超过目标最大 HP** |
| shield | 护盾 | 目标获得护盾值 = 施法者 atk × power；**先于 HP 吸收伤害**，耗尽即消失、不随时间衰减 |
| amp | 增伤 | 目标**下次攻击**伤害 +power 百分点；每目标独立持有、出手结算时消费并移除 |

- 技能机制预留：charge_free（免充能大招，《战斗系统》§3）；任意新 effect 枚举需制作人裁定后扩表，不属于常规新增。

## 4. 角色阵营（体系）

| 体系 | 特色 |
| --- | --- |
| 科技 | 科技武装、无人机、炮击、护盾 |

- **体系名与三界对应（世界观对齐 2026-09-20）**：科技=大秦文明（科技与机械法则）、魔法=诺兰大陆（魔法与元素法则）、仙道=九霄玄界（修仙与灵脉法则），依据 `docs/世界观/《汇界星痕》世界观设定.md` §8.3 天衡学院三系；英文 id 段 mech/arcane/xian 不变。characters.csv system/faction 列旧值（机律/秘法/玄门、机律联邦）→ 新值迁移，与 data_models.gd 枚举校验、character_designer.gd 枚举同步，归数值策划+系统程序执行（已登记交接班表）。

### 4.1 战斗定位（体系对应战斗方式）

角色体系实际对应战斗方式。每个体系均按以下 **5 种定位**设计角色，形成 3 体系 × 5 定位的设计矩阵（后续角色按空缺槽位补充）：

| 定位 | 职责 | 技能特征（典型） |
| --- | --- | --- |
| 单体输出 | 主 C，点杀关键目标 | 敌方单体高倍率伤害 |
| 群体输出 | 主 C，清场压血线 | 敌方整列/全体伤害 |
| 增伤副C | 输出兼增益 | 敌方伤害技能 + 友方增伤（amp） |
| 增伤辅助 | 纯增益引擎 | 友方增伤（amp）为主 |
| 生存辅助 | 续航与保护 | 友方治疗（heal）/护盾（shield） |

- **入队推荐公式**：标准三人编队 = **1 输出（单体/群体）+ 1 增伤辅助 或 增伤副C + 1 生存辅助**；新增角色设计与编队引导（T2.5 角色列表/编队提示文案）按此思路执行。
- MVP 三角色各占一席（§5）：科技-诺菈·星枢=生存辅助、魔法-艾蕾雅=增伤副C、仙道-洛清弦=群体输出；其余 12 槽位为后续角色设计方向。

## 6. 新增角色接口（按此流程零代码添加）

1. **设定**：制作人/剧情文案按 §2/§3 字段清单定稿（id/name/faction/system/背景/**战斗定位（§4.1 矩阵）**/技能名与效果枚举设想）。
2. **数据**：数值策划填 CSV——characters.csv 一行（§2 全列）+ skills.csv 两行（小技能+大招，§3 全列；技能 id 的体系段与序号段须与本节第 1 步定稿的角色 id 完全对应）。
3. **校验**：跑角色设计器（§7），PASS 后入库存档。
4. **资源**：美术按 T2.6 规范补占位/正式资源（`assets/portraits/<char_id>_<emotion>.png`、8 向帧条命名见推进表 §5.2）。
5. **生效**：DataManager 自动加载；角色列表/编队/战斗/立绘各系统自动消费，**业务代码零改动**。

约束：角色数量无上限（编队上限 3 归 Party）；name 列含「·」直接写；新体系扩展（如第四体系）需制作人裁定后改本文档与体系枚举，不属于常规新增。

## 7. 角色设计器（tools/character_designer.gd，headless 可跑）

| 功能 | 内容 |
| --- | --- |
| 校验 | characters.csv / skills.csv 全行：列数、枚举（system/type/target_side/target_scope/effect，空值按 §3 缺省 enemy/single/damage 回退）、id 规则（§2/§3，含技能 id 序号段与持有角色一致性）、引用存在（skill_small/skill_ult 在 skills.csv 中存在、cutscene_id 符合约定、portrait/sprite 经 ArtProvider 取纹理非空）、数值边界（四维正整数 ≥1、power>0、effect=amp 时须正整数百分点） |
| 冒烟 | DataManager 加载断言（角色数、指定角色字段回读）+ ArtProvider 取占位资源非空 |
| 报告 | 逐项 PASS/FAIL 明细，FAIL 含文件+行号；EXIT=0/1 |

- 使用时机：每次角色 CSV 变更后（新增/改数值/改技能）；与 tools/smoke_test_data_models.gd 互补（后者断言数据模型结构，本工具断言角色内容合规）。
- **WARN 档（提示级，不改变 EXIT 码）**：① target_side 与 effect 语义错配（`enemy` 配 heal/shield/amp，或 `ally` 配 damage）② background 为空（文案可后补）。**FAIL 档（阻断，EXIT=1）**：name 为空（§2 必填，角色列表与战斗直显此列）；列数 / 枚举 / id 规则 / 引用完整性 / 数值边界任一不符。
- 暂不校验：summon_pool.csv 引用与立绘情绪变体（T6.2 唤星接入后如需再补）。

## 8. 职责边界

- **数值策划**：四维/技能数值/权重，CSV 改动复跑设计器。
- **剧情文案**：name/background 文案、人设与台词一致性（人设基线见 §5）。
- **系统程序**：CharacterData/SkillData 模型、CSVParser 容错（新增列缺省值）、角色设计器工具实现。
- **战斗程序**：技能机制实现消费 power/scope/充能（一律引用《战斗系统》，不重复定义）。
- 设定冲突：世界观以 `docs/世界观/` 四篇为最高裁决，《初期设定》为游戏化概要；体系与队伍规则冲突以《队伍系统》/《战斗系统》为准。
