## 1. 交互对象分类

| 类别 | 名称 | 触发方式 | 使用场景 |
| --- | --- | --- | --- |
| A 类 | 按键交互体（Interactable） | 玩家靠近显示提示 + 按键触发 | NPC 对话、拾取点 |
| B 类 | 进入触发区（TriggerZone） | 玩家进入区域**自动**触发，无按键 | 主线剧情区域（T1.6，见 §5 预留） |

两类**复用同一信号** `EventBus.interact_requested(node)`，业务方按 `action_type` / meta 分发。

## 2. 规则 R1：靠近提示显隐

- **触发条件**：玩家碰撞体（collision_layer=2，T1.3 约定）进入交互体的检测区。检测区为 Area2D + 圆形 CollisionShape2D，**半径 60px，圆心 = 交互体脚底原点**（与 T1.2「实体 origin 在脚底」一致）。
- **系统行为**：头顶提示显示。提示 = 色块三角 + TextLabel（占位），文案格式：`{display_name} [E]`。
- **离开行为**：玩家离开检测区，提示立即隐藏。
- **边界**：
  1. 提示**不参与 Y-sort 遮挡**（置于不参与排序的层或提升 z_index），避免被前景地物盖住；
  2. 多个交互体各自独立显隐，互不联动（见 R3）；
  3. NPC 视觉原点必须在脚底，提示挂头顶上方。

## 3. 规则 R2：按键触发

- **输入 action 名**：`interact`；绑定 **E 键（KeyE）与空格键（Space）**，统一用 `physical_keycode` 绑定（T1.3 实证：keycode 绑定与注入/键盘布局不匹配）。
- **触发条件**：玩家处于至少一个 A 类交互体检测区内，且本帧 `Input.is_action_just_pressed("interact")`。
- **系统行为**：`EventBus.interact_requested.emit(self)`，`self` = 被触发的那个 Interactable 节点（携带对象引用）。
- **边界**：
  1. **范围外按键无效**：不发信号、无提示反馈；
  2. 单次按下只发一次信号，长按不重复；松开后可再次触发；
  3. MVP **无交互冷却**；对话/业务接管期间的防重复由业务层负责（对话时锁定玩家输入属 T4 范围，本系统不管）；
  4. 边缘抖动（按键瞬间刚好离开检测区）以按键当帧的重叠状态为准。

## 4. 规则 R3：多交互体并存裁决

- **提示**：所有在检测区内的交互体提示独立显隐（满足推进表验收「多个 NPC 同时存在互不干扰」）。
- **按键**：只触发**距离玩家最近**的一个。距离 = 玩家脚底到交互体脚底的平面（x-y）距离；距离相同按场景树顺序取先者。
- **边界**：触发后其余对象提示保持现状，不做额外变化。

## 5. 规则 R4：action_type 注册与信号契约

### 5.1 Interactable 导出属性（接口）

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `npc_id` | String | "" | 交互体唯一业务 ID（如 `awakened_mech_01`） |
| `display_name` | String | "" | 提示文案显示名 |
| `action_type` | String | `"talk"` | 交互动作类型，业务注册 |

- MVP 占位枚举：**`talk`**（对话，业务方按 `npc_id` 找 timeline 播放，T4.2/T4.4 消费）、**`open`**（开启/拾取类，T1.6 星砂结晶拾取用）。
- **扩展原则**：新增 action_type 由业务方注册；Interactable 本体**不硬编码任何业务行为**——只负责检测、提示、发信号。业务方（T1.6 拾取、T4 Dialogic 入口）监听 `interact_requested` 后按 `action_type` 分发。

### 5.2 信号契约（对齐 T0.4 EventBus）

- `interact_requested(node: Node2D)`：`node` 恒为 Interactable（或 B 类 TriggerZone）节点自身。
- 消费方读取：`node.action_type`、`node.npc_id`、`node.display_name`，附加标记走 `node.get_meta(...)`。
- **`npc_id` 唯一真相 = `Interactable.npc_id` 属性**；场景 meta 冗余仅作测试/标记用途，冲突以属性为准。

### 5.3 B 类触发区预留（T1.6 实现）

- 触发区 = Area2D（覆盖指定区域），玩家 `body_entered` → 发同一信号 `interact_requested`，node 上以 meta 携带 `main_trigger` 标记（供 T4.3 接 Dialogic 主线）。
- 触发区**只触发一次**（进入后至离开前不重复发，避免反复进出刷信号）；具体区域布置属 T1.6。

## 6. 边界情况总表

| # | 情况 | 规定行为 |
| --- | --- | --- |
| 1 | 玩家与 NPC 位置重叠 | 正常交互，不受影响；MVP NPC **无实体碰撞**（玩家可穿过，占位阶段不卡墙），后续 T2.3 如需阻挡另行变更规则 |
| 2 | NPC 隐藏/禁用（`monitorable=false` 或移出树） | 等同不存在：不显提示、不响应按键 |
| 3 | 玩家站在两个检测区交叠处按键 | 按 R3 触发最近者 |
| 4 | 信号发出后无业务消费 | MVP 允许（占位阶段打印日志即可），不重发；业务接入后由业务反馈 |
| 5 | 对话进行中玩家再按键 | 本系统不拦截；由对话系统锁定玩家输入解决（T4 范围） |

## 7. 验收对照（推进表 T1.5 三条验收 ↔ 本规则）

| 推进表验收项 | 对应规则 |
| --- | --- |
| 靠近提示出现、远离消失 | R1 |
| 范围内按键触发信号且带正确对象；范围外无效 | R2、R4 §5.2 |
| 多个 NPC 同时存在互不干扰 | R3 |
